# FTX-1 Пульт — удалённое управление Yaesu FTX-1

Полноценный пульт для FTX-1 (Field и Optima) через USB-кабель трансивера:
CAT-управление, звук приёма в колонки ПК/телефона, передача с микрофона ПК/телефона,
водопад, все регуляторы и всё меню EX трансивера.

```
 FTX-1 ──USB──► ПК с Windows (сервер: CAT + USB-звук) ──Wi-Fi/LAN/VPN──► браузер
                 │                                                    ├─ этот же ПК
                 └ http://localhost:8080                              ├─ другой ПК (Windows)
                                                                      └─ Android (ставится как приложение)
```

## Что умеет

* Частота VFO-A/B: круглая ручка-валкодер (вращение по кругу, 100 делений на оборот, инерция), цифры (колесо или клик по разряду),
  кнопки ±, стрелки клавиатуры, ввод с клавиатуры (`7.074`, `14200`, `145500000`).
* Диапазоны 160 м … 70 см с памятью последней частоты и вида работы; все виды работы.
* Шкалы: S-метр, при передаче — PO, SWR, ALC.
* Водопад + спектр с обзором «Авто» (по реальной полосе звука трансивера: в SSB ~3,5 кГц, в FM ~9 кГц) или 3–24 кГц, полоса фильтра, IF SHIFT, режектор, тон CW;
  двойной клик (двойной тап) — настроиться на сигнал.
* Шумодав пульта (только в FM): по шумоподавителю трансивера (SQL, команда RI) или по уровню; глушение «хвоста» после передачи — во всех видах работы.
* На мониторе любого размера пульт и панель помещаются в окно целиком, без прокрутки страницы (масштаб авто или вручную); на телефоне — прокручиваемая колонка.
* Приём: AF, RF, SQL, AGC, IPO/AMP1/AMP2, ATT, NB, DNR, DNF, ручной режектор, CONTOUR, APF,
  WIDTH, IF SHIFT, NAR, CLAR (RIT/XIT), двойной приём.
* Передача: мощность, MIC GAIN, PROC, AMC, VOX, монитор, CTCSS/DCS, сдвиг репитера, TXW,
  тюнер (встроенный SPA-1, внешний FC-40, ATAS).
* VFO/память: A→B, B→A, A⇄B, SPLIT, MAIN/SUB, скан, каналы памяти, QMB, LOCK, «мои частоты».
* CW: скорость, тон, ключ, BREAK-IN, 5 ячеек памяти ключа (пишутся в трансивер и передаются им самим).
* **FT8 и FT4** с автоматическим проведением связи и отправкой лога в HAMLOG-агент (UDP как WSJT-X).
* Декодер CW с ИИ-помощником, RTTY (приём и передача), метеофакс, NAVTEX, SSTV, PSK31 — см. ниже.
* **Меню EX целиком** — 402 пункта с поиском, чтением и записью.
* Консоль CAT для любых команд.
* Защита: передача снимается, если пропала связь с клиентом больше 1,5 с или превышено
  `max_tx_seconds`; одновременно передавать может только один клиент.

## CW · Морзе: декодер и ИИ-помощник

Вкладка «CW · Морзе» в пульте.

* **Декодер** расшифровывает телеграф из звука приёма в реальном времени: сам находит тон
  (или правый клик по сигналу на водопаде), сам определяет скорость 5–45 WPM, латиница или
  русская азбука. Распознаёт его встроенная цифровая обработка, как в fldigi.
* **ИИ-помощник** (LM Studio на этом ПК) после каждой передачи корреспондента исправляет ошибки
  декодера, переводит на русский с расшифровкой сокращений и Q-кодов, выделяет позывной, RST,
  имя и QTH и отмечает «Зовёт вас». Кнопка «✨ Ответ ИИ» составляет ответ по ходу связи.
* **Передача текстом**: поле с Ctrl+Enter и макросы CQ / Ответ / Рапорт / 73 / AGN? / QRZ?.
  По умолчанию текст передаёт сам трансивер из памяти ключа (по 50 знаков, ячейка 5).
  Можно манипулировать линией DTR/RTS второго порта (меню трансивера `CW_PC_KEYING`).
* **Автоответ ИИ**: когда корреспондент зовёт ваш позывной и закончил передачу, ИИ составляет
  ответ и через несколько секунд передаёт его (можно отменить; Esc — остановить). Отвечает,
  только если ваш позывной действительно есть в принятом; не больше заданного числа передач подряд.

**Настройка LM Studio**: загрузите модель (для 12 ГБ видеопамяти хорошо подходят Qwen2.5 7B/14B
Instruct, Gemma 3 12B, Mistral Nemo 12B), включите сервер: Developer → Start Server. Адрес и модель —
в панели управления сервером, карточка «ИИ и телеграф».

Языковая модель не «слышит» звук — она работает с текстом, который дал декодер.

**Без LM Studio всё работает**: декодер, передача, макросы и автоответ. Разбор принятого (позывной,
RST, имя, QTH, расшифровка сокращений) тогда делается по правилам CW-связи, а ответ — по шаблону
обычной связи (ответ на CQ → рапорт с именем и QTH → 73 SK). LM Studio лишь точнее исправляет
ошибки декодера и пишет ответы свободнее. Если сервер LM Studio выключен, пульт один раз сообщит
об этом и дальше молча работает по правилам.

## Запись связи

Кнопка «⏺ Запись» вверху пульта (клавиша H) пишет приём и передачу в один файл WAV
(16 кГц) в папку `records` рядом с программой. Последние записи можно скачать со вкладки
«Настройки» — в том числе на телефон.

## Голосовой автовызов

Вкладка «Передача» → «Автовызов голосом». До 5 сообщений: запись с микрофона этого устройства
или загрузка звукового файла (тишина по краям обрезается, громкость выравнивается). «В эфир» —
сообщение уходит по кругу: передача, пауза на приём, снова передача — заданное число раз.
Остановка: PTT, Esc, кнопка «Стоп» или сигнал в паузе не слабее выбранного (S3…S9).
Сообщения хранятся на сервере в папке `voice` рядом с программой.

## NAVTEX, SSTV, PSK31

Вкладка «Цифра» — разделы RTTY, Метеофакс, NAVTEX, SSTV, PSK31.

* **NAVTEX** — морские предупреждения и прогнозы на 518 кГц (а также 490 и 4209,5 кГц).
  Станции Чёрного моря (Новороссийск A, Керчь B, Одесса C, Стамбул D, Самсун E, Варна J…)
  с расписанием. Трансивер ставится в USB на 1,7 кГц ниже; заголовки ZCZC разбираются:
  какая станция и о чём сообщение. Перевод — кнопкой «Перевести (ИИ)» (нужна LM Studio).
* **SSTV** — картинки: Martin M1/M2, Scottie S1/S2, Robot 36, PD 90/120/180. Вид узнаётся
  по коду VIS, а если начало пропущено — по синхроимпульсам. Наклон и расстройка
  исправляются сами. Картинки сохраняются в папку `sstv`.
* **PSK31** — приём и передача (DATA-U). Правый клик по «ниточке» на водопаде — настроиться,
  дальше держит автоподстройка. Макросы CQ / DE / 73.

## Редактор каналов памяти

Вкладка «VFO/Память» → **Редактор каналов…** — полноэкранная таблица всех каналов, как в ADMS / RT Systems:
номер, группа, название (12 знаков), частота, вид, сдвиг (симплекс/+/−) и разнос, частота передачи, тон
(выкл / ENC / TSQ / DCS), CTCSS, DCS, кларифайер, заметка.

* **Прочитать** — каналы 001–999 (или «с … по …»); «тоны» — дочитать номер CTCSS/код DCS
  (трансивер на мгновение переключается на каждый канал с тоном и возвращается).
* Правки подсвечиваются; **Записать изменённые** — только они, с проверкой чтением (✔ / ⚠ у строки).
* Группы — свои (слева): назначение отмеченным, фильтр, переименование. Ещё: «← с VFO», перенос на другие номера,
  сортировка по частоте, отмена правок, поиск.
* Наборы каналов сохраняются на ПК (папка memory рядом с программой); импорт CSV (свой формат или из CHIRP)
  и экспорт CSV.
* Как пишется канал (проверено на FTX-1, прошивка 1.13): частота, вид, сдвиг, клар — командой MW;
  номер CTCSS и DCS — через VFO-A и AM («VFO-A в память»), после чего VFO-A и положение трансивера возвращаются;
  имя — MT, отдельная частота передачи («отд. TX») — MZ. Очистить канал по CAT нельзя; величина разноса
  ретранслятора общая для диапазона (меню FM → RPT SHIFT); группы трансивер не хранит.

### Каналы через флешку (пакетом, без CAT)

Трансивер сохраняет каналы на SD-карту (папка `FTX-1\MemList`, файл `ГГГГ_ММ_ДД_NN.dat`) и загружает их обратно.
В редакторе: **💾 Открыть с SD** — бэкап с флешки откроется в таблице; правьте; **💾 Сохранить для SD** —
получится новый `.dat` (с правильной контрольной суммой), его кладут в ту же папку и загружают в трансивере.

* Формат разобран и проверен загрузкой в FTX-1 (прошивка 1.13): шифрование байтов, CRC32 заголовка,
  карта занятых каналов, записи по 89 байт.
* Пишутся: частота, имя, вид (FM / FM-N / C4FM-DN; остальные виды сохраняются как были), сдвиг/отдельная TX,
  тон ENC/TSQ и CTCSS, новые и удалённые каналы. Всё остальное в записи остаётся как в исходном файле.
* Пока не поддерживаются: DCS, кларифайер, смена вида на AM/SSB, файлы настроек (`Menu`).
* Всегда оставляйте на флешке исходный бэкап — им можно вернуть всё как было.

## FT8 и FT4 — своя «MSHV» в браузере

Вкладка **FT8**: приём, передача и автоматическое проведение связи — с ПК или телефона.

* «Приём вкл» и выбор диапазона — трансивер сам встанет в DATA-U на стандартную частоту FT8/FT4.
  Расшифровка в конце каждого периода (15 с для FT8, 7,5 с для FT4); CQ — зелёным, вызовы вас — красным.
* **Нажмите на строку** — программа позовёт станцию и проведёт связь сама: локатор → рапорт → R-рапорт → RR73/73.
  **CQ** — звать общий вызов; первую ответившую станцию программа обработает сама. «Авто-CQ» — после связи снова CQ.
* Частота передачи — правый клик по водопаду или поле «TX, Гц». **Стоп** — немедленно прекратить передачу.
* Часы ПК должны быть точными (±0,5 с): рядом с часами показано среднее смещение dt принятых станций.
* **Лог**: каждая связь записывается в `ft8_log.adi` рядом с программой и отправляется по UDP в формате WSJT-X
  (по умолчанию 127.0.0.1:2237) — его принимают HAMLOG-агент, Log4OM, JTAlert, GridTracker.
  В программе лога включите приём от WSJT-X на этом порту. JTDX/MSHV при этом закройте — порт и звук должны быть свободны.
* Позывной, локатор, мощность, адрес лога — в «Настройках FT8» на той же вкладке.

**Новые страны и позывные** (как в JTAlert): строки помечаются цветом — фиолетовая метка: страна, с которой ещё
не было связи; оранжевая: страна не сработана на этом диапазоне; голубая: новый позывной; бледные строки — уже работали
на этом диапазоне. Фильтр «новые и мне» оставляет только их. О новой стране — всплывающее оповещение (можно со звуком).
На автоматическом CQ первыми обрабатываются новые страны. Чтобы учитывался весь ваш журнал, в «Настройках FT8»
загрузите его экспорт в ADIF (из HAMLOG); связи, проведённые в пульте, добавляются сами. Страны определяются по
cty.dat (Country Files, AD1C, www.country-files.com) — программа обновляет его сама раз в месяц.

**PSK Reporter**: принятые станции отправляются на pskreporter.info (раз в ~5 минут, как в WSJT-X/JTDX).
Блок «Меня слышат» показывает, кто принял ваши передачи за 30 минут, с расстояниями; «Карта» открывает карту на сайте.

Декодер и кодер FT8/FT4 — библиотека [ft8_lib](https://github.com/kgoba/ft8_lib) (Karlis Goba, лицензия MIT),
находится в `server/ftx/lib`. Автоматика связи, передача и лог — свои.

## RTTY (телетайп) и метеофакс

Вкладка «RTTY · Факс».

* **RTTY**: приём 45,45 / 50 / 75 / 100 Бод, сдвиг 170–850 Гц. Полярность (LSB/USB, «реверс»)
  определяется сама. «Автонастройка» находит пару тонов в полосе, правый клик по водопаду ставит
  центр декодера. Готовые настройки: любительский RTTY и метеосводки DWD (50 Бод / 450 Гц).
  Передача — звуком через USB (AFSK) в режиме **DATA-L/DATA-U**, макросы CQ / RYRY / 73.
  «Перевести (ИИ)» — перевод и пояснение сводки (только с LM Studio; приём работает и без неё).
* **Метеофакс (WEFAX)**: 120 строк/мин, IOC 576 (и 60/90/240, IOC 288). Картинка начинается
  сама по тону старта, фазирование выставляет край карты, наклон исправляется автоматически;
  по тону стопа карта сохраняется в папку `fax` рядом с программой (PNG). Клик по картинке —
  указать левый край вручную, ◀ ▶ — подправить наклон, ⛶ — во весь экран, 💾 — скачать PNG.
  Станции DWD (Пиннеберг): 3855, 7880, 13882,5 кГц — трансивер ставится в DATA-U на 1,9 кГц ниже.

Частоты и расписания станций меняются — сверяйтесь со свежими списками.

## Важно про водопад

FTX-1 **не передаёт картинку своей панорамы по CAT** — команда `SS` только меняет настройки
панорамы на экране трансивера. Поэтому водопад в пульте строится из звука с USB-кодека:
это полоса приёмника (до 24 кГц в зависимости от фильтра, на SSB полезно ~3–4 кГц), а не
широкая панорама диапазона, как на экране трансивера. Для FT8/CW/SSB этого хватает,
широкий обзор диапазона без дополнительного SDR-приёмника на этом трансивере невозможен.

## Установка (Windows)

Сначала установите драйвер **Virtual COM Port (CP210x)** с сайта Yaesu и подключите FTX-1 кабелем USB.
В «Диспетчере устройств» появятся *Enhanced COM Port*, *Standard COM Port* и звук *USB Audio CODEC*.

**Вариант А — готовый FTX1-Pult.exe** (Python не нужен): скачайте его со страницы
[Releases → latest](https://github.com/Evgeny161rus/ftx1-pult/releases/tag/latest) и запускайте двойным кликом.
Каждое изменение в ветке `main` пересобирает exe автоматически (GitHub Actions); собрать вручную — `build_exe.bat`.

**Вариант Б — без сборки.** Установите Python 3.10+ с python.org (галочка *Add python.exe to PATH*)
и запустите двойным кликом `FTX1-Pult.pyw`. При первом запуске программа сама предложит
установить нужные библиотеки.

### Окно «Панель управления»

При запуске открывается окно сервера (без консоли), а в трее появляется значок:

* **Трансивер** — COM-порт, скорость, звук приёма и передачи (отдельно) и способ PTT. Кнопка «Найти» подбирает FTX-1 сама
  (Enhanced-порт для CAT, Standard — для PTT, USB Audio CODEC — для звука).
* **▶ Запустить / ■ Остановить** — связь с трансивером; лампа показывает «на связи / не отвечает / ПЕРЕДАЧА»,
  рядом — частота и вид работы.
* **Открыть пульт** — пульт на этом ПК.
* **Телефон и другие ПК** — пароль, адреса и **QR-код**: наведите камеру телефона.
* **Запуск** — автозапуск вместе с Windows (в трее, без окна), сразу подключаться к трансиверу,
  открывать пульт при запуске, ограничение длительности передачи.
* **Подключены** — кто сейчас работает с пультом и кто передаёт; **Журнал** событий.
* **Выйти из программы** — полностью остановить сервер. Если окно просто закрыть, сервер
  продолжит работать в трее; повторный запуск программы откроет это же окно.

Настройки сохраняются сразу, вручную править `config.json` не нужно. Режим симулятора
(галочка в карточке «Трансивер») позволяет проверить всё без трансивера.

### Настройка трансивера для связи через микрофон ПК

В меню трансивера (вкладка «Меню» в пульте → кнопка «Показать эти пункты»):

| Пункт | Что задаёт |
|---|---|
| `SSB_MOD_SOURCE`, `AM_MOD_SOURCE`, `FM_MOD_SOURCE`, `DATA_…` | источник модуляции — выберите USB (номер значения сверьте с инструкцией FTX-1) |
| `…_USB_MOD_GAIN` | уровень звука с ПК в передатчик |
| `…_USB_OUT_LEVEL` | уровень приёма, уходящий в ПК |

Уровень подбирайте по шкале ALC: при нормальной речи ALC в начале зоны, без «зашкала».
Скорость CAT в меню трансивера должна совпадать со скоростью в панели (по умолчанию 38400).

## Телефон Android (и другие ПК)

1. Телефон в той же сети Wi-Fi, что и ПК с трансивером.
2. Наведите камеру на QR-код в панели управления (или откройте в Chrome адрес `https://192.168.x.x:8443`).
3. Сертификат самоподписанный: «Дополнительные» → «Перейти на сайт». HTTPS обязателен —
   без него браузер не даёт доступ к микрофону.
4. Введите пароль, заданный в панели управления.
5. Меню Chrome → **«Установить приложение»** — появится значок «FTX-1» как у обычного приложения.

Работа через интернет: не открывайте порт на роутере наружу, используйте VPN
(WireGuard, ZeroTier, Tailscale и т.п.) и адрес ПК внутри VPN. В настройках пульта
для мобильного интернета выберите качество звука 8 кГц.
На самом ПК с трансивером пульт по умолчанию работает в режиме 48 кГц — звук идёт без пересчёта частоты.

## Если что-то не так

* **«Порт не открывается»** — порт занят другой программой (WSJT-X, логгер): закройте её или настройте её на работу через flrig/rigctld.
* **«Трансивер не отвечает»** — не тот COM-порт (нужен Enhanced) или не совпадает скорость CAT.
* Подробности ошибок — в журнале панели и в файле `ftx1-pult.log` рядом с программой.
* **Нет звука приёма / пустой водопад** — в панели управления выберите вход «Микрофон (… USB Audio …)» и выход
  «Динамики (… USB Audio …)» трансивера (Windows может называть его *USB Audio CODEC* или *USB Audio Device*);
  в пульте нажмите «🔇 Звук»; проверьте `…_USB_OUT_LEVEL`. В FM при закрытом шумоподавителе водопад тёмный — это нормально.
* **Передача есть, модуляции нет** — `…_MOD_SOURCE` не USB для текущего вида работы
  или мал `…_USB_MOD_GAIN`.
* **PTT не включает передачу** — попробуйте `"ptt_method": "TX2"` или способ `RTS` через Standard-порт.
* **Эхо/свист на телефоне** — включите «Глушить приём во время передачи» и эхоподавление,
  используйте гарнитуру.

## Устройство программы

* `server/cat.py` — протокол CAT FTX-1: очередь команд, опрос, разбор ответов, Auto Information.
  Форматы команд сверены с CAT Operation Reference Manual 2508-C (по драйверу Hamlib для FTX-1).
* `server/audio.py` — USB-звук 48 кГц, передискретизация 16/8 кГц, БПФ для водопада, джиттер-буфер TX.
* `server/webserver.py` — HTTP/HTTPS + WebSocket без внешних библиотек.
* `server/sim.py` — симулятор трансивера и эфира (с телеграфистом UA3ABC, который проводит связь).
* `server/cw.py` — декодер и передача CW; `server/ai.py` — LM Studio и разбор без неё; `server/cwdesk.py` — ход связи и автоответ.
* `server/ft8.py` — FT8/FT4: слоты, автоматика связи, передача, лог ADIF и UDP; `server/ftx/` — модуль `_ftx` на основе ft8_lib (MIT), сборка `python server/setup_ftx.py build_ext --inplace`.
* `server/digi.py` — RTTY и метеофакс; `server/navtex.py`, `server/sstv.py`, `server/psk31.py` — NAVTEX, SSTV, PSK31; `server/digidesk.py` — их работа в сервере.
* `server/main.py` — сервер, панель управления, автозапуск, значок в трее.
* `FTX1-Pult.pyw` — запуск двойным кликом без консоли.
* `server/menu_ftx1.json` — таблица меню EX (402 пункта).
* `web/` — пульт (HTML/JS, ставится как PWA) и `panel.html` — окно управления сервером.

Отдельные калибровки шкал (PO, SWR, ALC) и таблицы полос WIDTH ориентировочные — уточняются
на реальном трансивере. Проверено на симуляторе; на живом FTX-1 первым делом проверьте PTT
и источник модуляции на эквиваленте нагрузки.
